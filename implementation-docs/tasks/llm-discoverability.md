# LLM & AI Discoverability

## Objective

Make solo-loft.com.ar straightforward for LLM-based assistants (ChatGPT, Claude, Perplexity, Gemini, and grounded search experiences) to crawl, extract, and cite, so the site surfaces when users ask for apartments or lofts in its covered zones — with zero added runtime cost and no performance regression (free-tier hosting preserved).

## Problem / Why

Current state (2026-10-18 inventory via delegated exploration):

- **No structured data**: zero `application/ld+json` anywhere in the repo. Crawlers/LLMs must infer entities (business, listings, prices, rooms, locations) from prose HTML alone.
- **No `llms.txt`**: no curated machine-readable entry point for LLM ingestion.
- **AI crawler allowlist not explicit**: `src/app/robots.txt` uses `User-Agent: *` + `Allow: /` — permissive, but AI-specific agents are not explicitly named.
- **Language declared wrong**: both route-group root layouts render `<html lang="en">` on an all-Spanish site.
- **No canonical URLs**: `buildMetadata` sets no `alternates.canonical`; `/ad/[slug]` duplicates `/properties/[slug]` content with cross-pointing metadata and no canonical.
- **Freshness fields absent** from the property fragment: `publishedAt`/`updatedAt` exist in the Hygraph schema but are queried only by the sitemap fragment.
- **Pre-existing risks observed** (not in scope unless the user asks): listing queries cap at `first: 50` while the sitemap query is unbounded; `/api/webhook/revalidate` has no auth check; `/ad/[slug]` duplicates content.
- **Baseline strengths**: server-rendered cached content (`"use cache"` + `cacheLife`/`cacheTag`, Hygraph webhook revalidation), dynamic sitemap with `lastmod`, per-page `generateMetadata`, OG/Twitter images, Vercel + Hygraph free tier.

## Constraints

- **Free tier only**: no new paid services, accounts, or external APIs with runtime cost; Hygraph free-tier query budget respected (reuse existing cached services, no new unbounded queries).
- **No performance regression**: JSON-LD is static inline markup; `llms.txt` must be one CDN-cached route; no new client JS; no added per-request compute beyond existing cached patterns.
- Keep Next.js 16 patterns: `"use cache"`, `cacheLife`/`cacheTag`; no new `dynamic`/`revalidate` route exports.
- No new runtime dependencies. User-requested deviation (2026-10-18): `schema-dts` added as a devDependency (type-only, zero runtime cost).
- Git: the agent must not run `git add` or `git commit`; the user stages and commits manually (2026-10-18 session preference).
- User-facing content strings ES-AR; code and comments English.
- RDD is off (global) for this repository: verification = lint + build + runtime checks; no native review lifecycle.

## Acceptance criteria

- L1: rendered HTML of `/properties/[slug]` and `/properties` contains valid, parseable `application/ld+json` scripts with the declared types/fields; `pnpm lint` and `pnpm build` pass; no client-side changes; inline JSON-LD measured 5.0–6.0 KB uncompressed per property page (dominated by the full description text, deliberately not truncated — it is the highest-value LLM content).
- L2: `/llms.txt` returns `text/plain`/`text/markdown` markdown with every listing-page property and correct absolute URLs; served with long-lived CDN cache headers.
- L3: `robots.txt` still allows all crawlers; AI agents explicitly listed; sitemap line preserved.
- L4: both layouts emit `lang="es-AR"`; every page emits a canonical URL; ad pages canonical to `/properties/[slug]`.
- L5/L6: only if approved.
